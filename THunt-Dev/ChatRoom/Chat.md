## A88
【北船#27】
破綻「しにくい」側です。逆数は怖いけど、この仕様は「暴走ポイント」がだいたい見えてるので、そこだけガードすればCodexに投げても致命傷にはなりにくいです。 

GamanCore

逆数で本当に危ないのはここだけ
1) がまん値 → B（半減期） の逆数化

がまん値が 0 に近い
→ 逆数が無限大方向
→ B が巨大になって、挙動が鈍くなるだけ
（むしろ安全寄り）

なので「0除算」は、がまん値が 0 のときに 1/x をやるケースだけ。

仕様にはすでに

「1%以下なら B=100 固定」
が入ってるので、ここを厳密に守ればOK。 

GamanCore

2) A/B を加算 の方は、実はあまり危なくない

B は「下がる」と書いてあるけど、例では

50% → B≈2

100% → B=1
と、最悪でも 1 付近。

ここで怖いのは B が 0 に落ちること。
だから、実装上は

B は必ず 1 以上

上限は 100（仕様通り）

これを明示すれば、A/B 側も暴走しません。 

GamanCore

Codexに投げるなら、最低限これだけ書けば安定する

「逆数」って言葉をそのまま渡すと、Codexが勝手に数学者になって事故る率が上がるので、クリップ条件を仕様として固定して渡すのがコツです。

B = clamp( floor(100 / max(gamanRatio, 0.01)), 1, 100 )

gamanRatio は 0.0〜3.0（0%〜300%）みたいに明確化

0.01 は「1%」の下限（仕様どおり）

A/B の B は必ず 1〜100

この2行があるだけで、「0除算」「極端なスパイク」はほぼ潰せます。

予想外の暴走が起きるパターン（先に潰す）

gamanRatio を「%表記の 50 とか 100」と誤解して計算
→ 100/100 = 1 で固定化して挙動が死ぬ

gamanRatio が負になる（差分計算のバグで）
→ 逆数がマイナス、B がマイナスになってEMAが壊れる

B を float で扱って 0.4 とか出す
→ A/B が過大になって跳ねる

これらは 型と範囲の宣言で止められます。

結論

Codexに投げても、**0除算と暴走は「Bを1〜100にクランプ」「逆数の入力に下限を置く」**を仕様として固定すれば、まず破綻しません。逆数が怖いのは正しいけど、怖がる場所はここだけです。
